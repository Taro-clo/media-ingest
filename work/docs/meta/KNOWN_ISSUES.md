## KI-1 无 `Season N` 层级时改名被静默跳过

**状态：搁置 —— 改名行为不变，只以看板待办的形式提示。**

对命中本条的每个作品，应用**仍不改名、不移动**，也不把它算成「集数未解析」；它只是多出一条待办
`unscoped_works`（「作品结构不可识别（未改名）」）。「扁平目录模式」**未实现**。

**现象**：作品目录下没有 `Season N` 这一层时，重命名阶段一个文件都不改；任务**不报错**
（可为 `success`，`renamed = 0`），目标侧硬链接照常建好、文件名保持源原名。
**建链与改名是两件事**：不生效的只是改名。

**触发条件**（三条同时成立）：媒体库 `traverse.file_scope = subdir`；`traverse.accept_dirs` 非空且只接受季目录
（如 `["^Season (\\d+)$"]`，`bangumi` 处理器默认如此）；某个一级作品目录的直接子目录里没有整名匹配
`accept_dirs` 的目录（`fullmatch`，所以 `Season 1 (2018)`、`SP`、`特典` 都不算匹配）。
**规模**：命中比例随源库而变（在 54 个作品的样本库里 8 个命中）；这些作品的文件在目标侧全部以源原名存在，**数据不缺失**。

**怎么办**：

- 想改这些作品 → 在**该库**的「重命名规则（本库）」覆盖里把 `traverse.file_scope` 改成 `title`
  （作用域 = 作品目录本身）。注意此时 `season` 是空串，命名模板里的 `{season:02}` 会渲染成 `00`，
  且 `title` 模式不过滤非文件项、作用域变大 —— 先确认目录里没有不该动的文件。
- 不想改 → 看板上确认 `unscoped_works` 待办并接受现状即可。

**不改的原因**：`accept_dirs` 不匹配就跳过是冻结的遍历语义；改成"再兜底一层"会让"用户显式写了接受规则"
的意图变含糊，需要改基线契约。若以后真要做，先用**库级覆盖**验证命名模板表现。

相关：遍历语义见 [`../contracts/PROCESSORS.md`](../contracts/PROCESSORS.md) §4；可观测字段
`RenameOutcome.unscoped_works` / `result.unscoped_works`（同样进 `samples`），去重键 = 作品目录。

## KI-7 升级后首次全量运行会重链并可能多出重复文件名

**状态：已知且被接受的一次性影响（不是缺陷）。** 老媒体库才有的现象，新库不会遇到。

**现象**：老库的 `link_records` 账本是空的（刻意不回填历史 `hard_links.log`），首次全量运行会把每个作品
重新建链；如果此前在目标里改过某些文件名，会以**原名**再链一份 —— 同一 inode 的第二个目录项，重命名阶段
两个目录项争同一个目标名，于是多出 `xxx (2).mkv`（冲突加后缀口径见 [`../contracts/PROCESSORS.md`](../contracts/PROCESSORS.md) §4）。

**为什么不回填**：`hard_links.log` 是全局的、不含库/目标维度，无法可靠映射成「某库某作品已处理」。

**影响与规避**：**不丢数据**（多出来的是硬链接，源目录不受影响），只是目标目录多了重复文件名。
三选一：① 升级后使用**新媒体库**（推荐）；② 先清空目标目录再跑首次全量；③ 在「作品记录」里逐作品
**删除记录**后重做。重链过一轮后账本即有记录，后续恢复正常跳过。

## KI-8 「作品记录」页的搜索是朴素子串、目标侧计数只覆盖当前页

**状态：已知且刻意保持（不是缺陷）。** 只影响"看一眼"的便利性，不影响任何写入行为。

**现象**：

1. 搜索把输入转义后做**子串**匹配（`folder LIKE '%…%' ESCAPE '\'`），只匹配**作品名**（源一级文件夹名）：
   不支持正则 / 多关键词 / 日期范围；搜改名后的名字、作品内部文件名、目标路径片段一律搜不到；
   `%` `_` `\` 按字面处理；仅在当前选中的库里搜。
2. 「目标里现在有 N 个文件」等计数（`target_files` / `target_bytes` / `target_loose`）是对**当前页**每个作品
   **现场读磁盘**算出来的；信息行的「命中 N 条 / 本库共 M 条」与两本账差集才按整本账算，不受搜索与翻页影响。

**为什么**：账本键是 `(library_id, folder)`、**作品级**、不存文件清单，所以"当前有几个文件"只能现场算；
对整库翻页之外再全量扫盘会把一次翻页变成一次全库 IO。搜索刻意做成最保守的子串（任何输入只缩小结果、不报错）。

**怎么办**：搜索与计数都**只读**，「删除记录 / 立即重命名」始终作用于显式勾选的作品（勾选跨页保留）。
要按别的维度找，直接调 `GET /api/libraries/{id}/works?q=&limit=&offset=`（见 [`../contracts/API.md`](../contracts/API.md) §3.10）
或先按作品名搜到大概范围再翻页。**没有**"整库健康扫描"功能：不要拿某一页的计数当整库结论。

相关：账本语义见 [`../contracts/COMPATIBILITY.md`](../contracts/COMPATIBILITY.md) §3.5；
页面说明见 [`../guides/USER_GUIDE.md`](../guides/USER_GUIDE.md) 的「作品记录」一节。

## KI-9 单作品 `force=true` 仍会把已改名的文件按原名再链一份

**状态：已知、界面无法触达、是否退役待定。** **单作品** `force=true`（`scope.mode="folder"`）是刻意保留的接口用法，
但会复现整库 `force` 被撤掉所针对的现象：建链阶段把**已改名的文件按原名再链一份**，目标作品夹里同一 inode
出现两个目录项，重命名阶段多出 ` (2)` 后缀。运行弹窗与「作品记录」页都不会发 `force=true`。

**触发**：`POST /api/libraries/{id}/run` 带 `{"force": true, "scope": {"mode": "folder", "folder": "<作品名>"}}`。
**为什么跳过判据会被摘掉**：`force` 的语义就是"不跳过、重新处理一遍"，否则强制重跑会变成静默空操作；
而"重新处理"按**源目录原始文件名**建链。

**影响面**：正常使用完全碰不到。接口用户只应在"目标目录已空/残缺"的排查场景使用，**不要**用它补目标里缺失的文件。
要让某个作品回到干净状态：在「作品记录」里**删除该作品记录**（连带删目标作品夹）再跑普通执行；
或手工删掉目标作品夹后删记录重跑。只删 ` (2)` 文件而不删记录的话，普通运行会照旧跳过（见 [KI-7](#ki-7-升级后首次全量运行会重链并可能多出重复文件名)）。

**待定**：后续版本是否让 `force=true` 一律 400（彻底退役、只留两条正道）。

相关：整库 `force` 已停用（返回 400，见 [`../guides/USER_GUIDE.md`](../guides/USER_GUIDE.md) 的「运行」一节）；
账本语义见 [`../contracts/COMPATIBILITY.md`](../contracts/COMPATIBILITY.md) §3.5；
测试 `tests/test_works_ledger.py`（覆盖 `scope.mode="works"` / 删除 / 立即重命名，**不覆盖**单作品重复建链）。

## KI-10 待办看板的作品筛选是朴素子串、不是精确归属

**状态：已知且刻意保持（不是缺陷）。**

**现象**：待办看板的「作品」筛选（`GET /api/todos?q=`，输入停 0.4 秒后自动筛）匹配的是**待办自己的文字** ——
`title` / `detail` / `dedupe_key` 三列任意一处包含该文字即列出，**不是**"这条待办属于哪个作品"。
搜 `Work 1` 会同时列出 `Work 12`；同一段文字出现在别的条目里也会被列出。ASCII 大小写不敏感，
`%` / `_` / `\` 按字面；与状态/种类/媒体库筛选是 AND 关系，`total` 与翻页按过滤后算；
顶部计数与「一键检测」始终是整表/整库口径。

**为什么**：`todos` 是全局一份台账，表里没有 `folder` / 作品列，作品名只出现在摘要、详情与去重键里。
要精确归属得改数据模型并回填历史条目、改五种样本的写入路径，收益只是"少列几条"；"按路径猜归属"被否决
（源一级文件夹名 ≠ 作品，猜错会漏列，筛漏比多列更危险）。

**怎么办**：写更长的子串（`Work 03` 而非 `Work 0`），或配合状态/种类/媒体库筛选收窄。
接口上 `q` 缺省/空串/纯空白 = 不过滤，没有任何取值会 400。

相关：看板语义见 [`../guides/USER_GUIDE.md`](../guides/USER_GUIDE.md) 的「任务与待办」一节、
[`../contracts/API.md`](../contracts/API.md) 的待办列表端点；测试 `tests/test_todos.py`。

## KI-11 命名里出现未知变量时，段序列静默少一段

**状态：当前行为。** 保存期拦住新写的错名字（422），运行期对老配置只**留痕不拦截** —— 不再有"任务成功却什么都没说"。

**现象**：命名（`naming.segments` 的 `param` 段，或 `naming.template` 里的 `{名字}`）写了上下文里**不存在**的变量名时，
那一段什么都不输出（文件名少一段），任务照样 `success`；极端情况下段序列全为未知名字 ⇒ 渲染出空文件名 ⇒
走兜底"已跳过"。**保存期**会 422 点名未知变量（`validate_spec()` 用有效名字集合校验）；
**运行期**对老配置 / 手写 YAML 收集并留痕：任务结果 `result.unknown_params`（计数）、
`result.samples.unknown_params`（`{label, file, params}`）、`warnings[]` 一条汇总 + 日志逐条 WARNING。

**谁会踩到**：处理器编辑页的段下拉框几乎不会（选项来自变量表）；模板框能写但当场报错；媒体库覆盖模板保存时被拦；
**手写 / 导入 YAML** 与直接改库里 spec 不会被拦（靠运行期留痕）。

**怎么办**：任务详情的橙色告警区与日志会点名「作品名/Season N/文件名 · 变量名」，去编辑页把名字改对后重跑该作品。
升级注意：保存**已经存在的**带未知名字的旧配置会被 422 拦住（校验在保存路径，读取路径照旧能跑）——
要在编辑页改别的字段时先把那一段删掉或改成合法名字。

**为什么不做成"未知名字直接失败"**：段序列渲染契约是"查不到就留空、绝不抛异常"（不能因为命名里一个错字让整个作品停摆）。
**为什么不加新待办种类**：未知变量属于"配置写错"，改一次就不会再有，任务计数 + 日志足够定位，不占用待办板。

相关：变量表与表达式见 [`../contracts/PROCESSORS.md`](../contracts/PROCESSORS.md) §3；
有效名字集合 `known_context_names()` 与前端 `knownContextNames()` 同一口径；测试 `tests/test_processor_spec.py`、
`tests/test_processor_engine.py`、`tests/test_library_overrides.py`；排查步骤见
[`../guides/TROUBLESHOOTING.md`](../guides/TROUBLESHOOTING.md) 的「命名」相关场景。

## KI-12 目标目录被手工删除但作品账本仍在

**状态：已记录，暂时搁置 —— 不修。** 官方重做路径「作品记录 → 删除」不会留下这个状态，只有**手工删掉目标目录**才会踩到。

**现象**：目标根被人在文件管理器里删掉后再对整库点「运行」：任务 `status=failed`、`result` 里 `linked 0 / skipped N`、
耗时几百毫秒、看板多一条 `task_failed`，错误形如
`无法读取媒体库目录 <目标根>：[Errno 2] No such file or directory`。源目录一个字节都没动，但链接一个都没重建。

**机制**：账本只比对「源目录 + 目标目录 + 文件夹体积」，**不看目标目录是否还在**；命中"已记录且体积一致"就跳过，
目标根只在真正建链时才创建 ⇒ 全部跳过时目标根根本不建；随后改名阶段读库目录 ENOENT，整任务失败。

**触发**：「作品记录 → 删除 / 改名」都不会（前者连目标夹一起删并清账本，后者有目标根守卫 400）；
**整库运行**端点没有同款守卫；手工 `rm -rf` 目标根 / 换挂载盘 / 迁移时漏掉目标树会留下此状态
（账本在 `/data/mlm.db`，目标树在媒体盘）。

**怎么办**：把目标根目录建回来（空目录即可）再跑；或删掉相关记录重跑。
官方候选修法（三条，**未实施**）：① 建链阶段即使全跳过也 `makedirs(目标根)`；② 目标根不存在时账本一律不算数；
③ 给整库运行端点补目标根 400 守卫。三条都指向同一事实：**账本记的是"我处理过"，不保证"东西还在"**。

**同一根因的旁证**：删掉目标树后在**同一份数据库**上复跑全量验收 → `linked N / renamed 0`：
链接被重建但改名阶段什么都没做（"逐文件决策缓存与目标树不同步"）。因此验收 harness 必须在**全新数据库**上跑
（见 [`../../scripts/README.md`](../../scripts/README.md)）。
